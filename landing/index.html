Apps can't touch the platform

                
Builds and apps run as their own unprivileged user, bound to loopback behind Nginx. A bad dependency script can't read ShipYard's keys or open a public port.

            Questions
          

          

            

              What do I need to run it?
              
A Debian or Ubuntu server you can reach over SSH, a user with sudo, and ideally a domain. The installer handles the rest: Nginx, certbot, PostgreSQL, Redis, Bun, Node.js and the process manager.

            

            

              Do my apps run in Docker?
              
Not by default. Apps run as supervised processes behind Nginx, which keeps a small server light. If you prefer containers, there's an optional Docker mode.

            

            

              What does it cost?
              
Nothing. ShipYard is open source under the MIT license, with no plans or per-app pricing. You pay for your own server, and you can run as many apps on it as it can handle.

            

            

              Can other people sign in?
              
You sign in with GitHub, and the first account becomes the owner. Sign-ups stay closed until the owner opens them in Settings.

            

            

              What happens when a deploy fails?
              
A failed build or pre-deploy command never touches the live app: the current version keeps serving, and the logs show exactly where it stopped. If something slips through, roll back to an earlier build from the dashboard.

            

            

              What survives a reboot?
              
Everything. The process manager brings ShipYard and every deployed app back up when the server restarts.
